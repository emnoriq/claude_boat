# 堅いレース.ai v5 精度最大化仕様書

## 1. 現状分析（v4バックテスト結果: 3日間384レース）

| 指標 | 値 | 問題点 |
|------|-----|--------|
| 全体的中率（三連複BOX 3艇） | 22.1% | 業界平均（20%）と大差なし |
| Top4プラン的中率 | 3/12 = 25% | 転がし不可能 |
| 堅さスコア「堅い」ゾーンの的中率 | 26.9% | 全体比+5%しかない |
| 予想3位の外れ率 | 56.9% | **最大の弱点** |
| 予想4位が3着内に入る率 | 46.4% | **見逃している有力候補** |
| 2艇一致率 | 82.8% | 2/3は当たっている |

### 致命的な問題
1. **3位候補の選定精度が低い** → 3位と4位の判別ができていない
2. **堅さスコアが機能していない** → 「堅い」と判定しても的中率がほぼ変わらない
3. **データ不足** → 風・天候・潮・コース別成績を使っていない
4. **静的な重み** → 結果データで検証されていない固定値

## 2. v5 改善方針

### 2.1 コアアーキテクチャ: 多段フィルタ方式

```
[全レース ~120/日]
    ↓ Stage1: 拡張スコアリング（追加データ活用）
[各艇の力スコア 0-100]
    ↓ Stage2: 動的BOX選定（3艇 or 4艇を自動判定）
[最適BOXチケット]
    ↓ Stage3: レース堅さの再定義（回帰的キャリブレーション）
[信頼度ランキング]
    ↓ Stage4: プラン選定（条件フィルタ + ランキング）
[最終4レース + 買い目]
```

### 2.2 追加スクレイピングデータ

boatrace.jp から無料で取得可能な追加データ:

| データ | URL | 用途 |
|--------|-----|------|
| 風速・風向 | beforeinfo ページ | 追い風=イン有利、向かい風5m+=アウト有利 |
| 波高 | beforeinfo ページ | 高波=実力差が出にくい |
| 天候 | beforeinfo ページ | 雨=スタート乱れやすい |
| 水面状況 | beforeinfo ページ | 安定/不安定の指標 |
| コース別成績 | racelist ページ拡張 | 選手の得意コース |
| 当地勝率 | racelist ページ | 会場との相性 |
| フライング回数 | racelist ページ | F持ち=スタート慎重→不利 |
| 体重 | racelist ページ | 軽い選手が有利（特にアウト）|

### 2.3 スコアリング改善（v4→v5）

#### A. 艇の力スコア計算

| 要素 | v4配点 | v5配点 | 変更理由 |
|------|--------|--------|----------|
| コース×級別 | 0-40 | 0-35 | 他要素の比重を上げるため削減 |
| 会場イン率補正 | ±2 | ±4 | 会場差の影響をより反映 |
| 全国勝率 | 0-22 | 0-20 | 適正化 |
| 当地勝率 | なし | **0-8** | **新規追加: 会場相性** |
| モーター2連率 | 0-8 | 0-10 | モーター影響を増加 |
| ボート2連率 | なし | **0-5** | **新規追加** |
| 平均ST | -3~5 | -3~5 | 維持 |
| 展示タイム | -2~8 | -2~8 | 維持 |
| スタート展示 | -4~4 | -4~6 | F持ち選手のペナルティ強化 |
| 風補正 | なし | **-5~+8** | **新規: 風向×コースの影響** |
| 体重補正 | なし | **-2~+3** | **新規: 軽量=加速有利** |

#### B. 風の影響モデル

```
追い風（風速1-2m）:
  1コース: +3  2コース: +1  3コース: 0  4-6コース: -1

追い風（風速3m+）:
  1コース: +5  2コース: +2  3コース: -1  4-6コース: -2

向かい風（風速1-2m）:
  1コース: -1  2コース: 0  3コース: +1  4-6コース: +1

向かい風（風速3-4m）:
  1コース: -3  2コース: -1  3コース: +2  4-6コース: +3

向かい風（風速5m+）:
  1コース: -5  2コース: -2  3コース: +4  4-6コース: +5
  → 堅さスコアも大幅減（荒れやすい）
```

#### C. 動的BOX選定（3艇 or 4艇）

v4の最大の弱点「3位と4位の判別不能」を解決:

```javascript
// 3位-4位のスコア差を計算
const gap34 = sorted[2].score - sorted[3].score
const totalRange = sorted[0].score - sorted[5].score
const relativeGap = gap34 / totalRange

if (relativeGap < 0.15) {
  // 3位と4位が僅差 → 4艇BOX（4C3 = 4通り）
  boxSize = 4  // 投資: ¥400（4通り×¥100）
} else {
  // 3位と4位に明確な差 → 3艇BOX（1通り）
  boxSize = 3  // 投資: ¥100（1通り×¥100）
}
```

### 2.4 堅さスコアの再定義

v4の堅さスコアは的中率と相関が弱い。v5では**実績データから逆算**した重みを使用:

| 要素 | v5重み | 根拠 |
|------|--------|------|
| 1コースA1（勝率7.0+） | +25 | バックテストで最も安定 |
| 1コースA1（勝率6.5-6.9） | +18 | |
| 1コースA2（勝率6.0+） | +12 | A2の方がむしろ的中率高い（27.3%） |
| 会場イン率60%+ | +10 | 大村・徳山・芦屋の安定性 |
| 会場イン率55-59% | +6 | |
| 外コースA1 | -12 | 荒れる最大要因 |
| 外コースA1（勝率7.0+） | -8追加 | |
| 追い風 | +5 | イン有利=堅い |
| 向かい風5m+ | -15 | 荒れる |
| Top3-4スコア差(相対) | 0-15 | BOX的中に直結 |
| 展示データ整合性 | 0-8 | 維持 |
| **波高1cm以下** | **+5** | 静水面=実力通り |
| **波高5cm+** | **-8** | 荒水面=波乱 |
| **雨天** | **-5** | スタート乱れ |

### 2.5 プラン選定の改善

v4: 堅さTOP4を時刻順にソート
v5: 条件フィルタ → 重み付きランキング

```
フィルタ条件（必須）:
  - 堅さスコア >= 45（v4では閾値なし）
  - 向かい風5m以上でないこと
  - 波高10cm以上でないこと
  - 出走取消・フライング選手がいないこと

ランキング方法:
  - 堅さスコア × 0.6 + BOX的中期待値 × 0.4
  - 同一会場からは最大2レースまで
```

### 2.6 収支シミュレーション表示

個人用のため、具体的な収支を表示:

```
1レース投資: ¥100 × チケット数（3or4枚）
期待払戻: 三連複の平均払戻 × 的中確率
期待収支: 期待払戻 - 投資額
ROI: 期待払戻 / 投資額
```

## 4. 技術仕様

### 4.1 データ取得フロー

```
毎日のデータ取得（2段階）:

[Phase1: 前日夜 or 当日朝] ← cron 23:00 JST
  racelist ページから基本データ取得
  → 選手情報、級別、勝率、モーター率、当地成績

[Phase2: レース開始1時間前] ← cron 08:00 JST
  beforeinfo ページから直前情報取得
  → 展示タイム、スタート展示、風向風速、波高、天候
```

### 4.2 ファイル構成の変更

```
src/lib/analysis.js → analysis-v5.js（新エンジン）
  - scoreBoat()      : 各艇スコア（風・体重含む）
  - selectBox()      : 動的BOX選定（3 or 4艇）
  - calcFirmnessV5() : 新堅さスコア
  - selectPlan()     : フィルタ+ランキング
  - calcROI()        : 収支期待値

src/lib/raceData.js → 拡張
  - parseBeforeInfo() : 風・波・天候パース追加
  - parseRaceList()   : 当地勝率・F回数・体重パース追加

api/scrape-all.js → 拡張
  - beforeinfo ページも取得

scripts/scrape-date.mjs → 拡張
  - 同上

src/App.jsx → 簡素化
  - 認証削除、全機能フリー

src/components/KorogashiPlan.jsx → 拡張
  - 風・波・天候表示
  - 動的BOX表示（3艇/4艇）
  - ROI表示
```

## 6. 実装順序

1. **追加データスクレイピング** ← 風・波・天候・当地勝率
2. **分析エンジンv5** ← 新スコアリング + 動的BOX + 新堅さ
3. **UI簡素化** ← 認証削除 + 新表示
4. **バックテスト比較** ← v4 vs v5 で定量検証
5. **デプロイ + 運用開始**
